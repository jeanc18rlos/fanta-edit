# Hostile-edit corpus

Each folder is a small Fanta project with one edit made outside Fanta.
`<case>.expected.json` lists what a checker must report for it, in order:
the code, the severity, and the file and line where there is one. Messages
are not part of the contract.

```sh
cargo run -p fanta-format --bin fanta-check -- crates/fanta-format/tests/corpus/merge-conflict --json
```

| Case | The edit |
| --- | --- |
| `pristine` | None |
| `reformatted` | JSON minified; CSS and SVG re-indented and re-wrapped, as a formatter would |
| `deleted-page-svg` | A page's SVG deleted |
| `deleted-records` | A page's `nodes.json` deleted |
| `renamed-id` | A node's `id` changed in the SVG only |
| `pasted-element` | An element copied and pasted, with its `id` |
| `resaved-by-vector-app` | The page SVG rewritten the way a vector application saves: its own namespaces and metadata, paint folded into `style`, attributes reordered |
| `merge-conflict` | Conflict markers left in a stylesheet |
| `missing-token` | `var()` naming a token no variable produces |
| `deleted-component` | A component's folder deleted while an instance remains |
| `missing-asset` | An image file deleted while the index lists it |

Repairable from the files alone: `renamed-id`, `pasted-element`,
`merge-conflict`, `missing-token` and `resaved-by-vector-app`. The four
deletion cases need the deleted file from a snapshot or a commit, and the
corpus folders carry no history.

`reformatted` and `resaved-by-vector-app` are written by the generator, not
by running a formatter or a vector application.

The folders hold only what a load reads. They are generated by the
`regenerate_corpus` test in `../check_corpus.rs`; node ids change on every
run, so regenerate only to add or change a case and review the diff.
