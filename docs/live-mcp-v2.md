# Live MCP v2 + native agent design tools

The program that makes fanta-edit's design surface (fig_viewer) drivable by
agents — external ones over MCP and the built-in agent panel natively — plus
media generation (image/video via api.fantaisa.net) and collaboration.

## What we learned (research pass, 2026-07-11)

**The old system** (`~/fanta`, winit+egui): `crates/fanta-app/src/app/live_mcp/`
(~38.7k lines, 53 files) served 207 tools — 173 builtins (transport.rs
`BUILTIN_TOOLS`) + 34 write-plane `DocTool`s from `fanta_ai::all_tool_specs()`
— over a hand-rolled localhost server (TCP 127.0.0.1:3846, env
`FANTA_MCP_ADDR`) speaking both JSON-lines and Streamable HTTP `POST /mcp`,
Origin-checked to localhost, 16MB cap. A `fanta-mcp` stdio binary proxied
stdio→TCP for Claude Code/Codex configs. A headless harness drove the same
dispatch chokepoint in CI. Writes went through one seam
(`registry::apply_write_tool`): preview-validate on a doc clone →
`vcs.validate_ops` → apply → `solve_layout_after_ops` → flash + reveal
selection. `journal.rs` recorded every tool call.

**The new surface** (fanta-edit): fig_viewer renders `Doc` from the shared
engine repo (`../fanta-engine-migration/crates/fanta-doc` — same lineage as
the old app's, evolved: adds motion.rs). `.fig` files and `fanta.json`
projects open in the canvas (`FigItem: project::ProjectItem`); `.fnx` sources
are a **React/TSX-style DSL** (JSX element = scene node, attributes = serde
fields of NodeData) generated by `fanta_fnx::encode_subtree`, edited as text
with TS LSP, validated + hot-reloaded into the canvas (300ms debounce built
for "an agent rewriting several project files").

**The reference designs** (Figma MCP, Pencil MCP): don't ship 200 tools.
Figma ships ~3 read tools + ONE general write tool (`use_figma` = Plugin-API
JS eval) + a skill that teaches the API. Pencil (native canvas, like us)
ships `get_editor_state` / `batch_get` / `batch_design` (JSON op list) /
`get_screenshot` / `get_guidelines` / `snapshot_layout`. The old live_mcp
already had `batch_get`/`batch_ops` — v2 promotes them to the primary verbs.

**The backend** (api.fantaisa.net): `/mcp` already serves 14 metered tools —
generate_image, edit_image, upscale_image, vectorize, animate_image,
transcribe, plan_compose, get_generation, list/search_assets, upload_asset,
remember/recall, list_models, get_credits. Auth = `Bearer fnt_live_…`.
Long jobs poll internally (60s budget) then hand back a generation_id.

## v2 architecture

### 1. `crates/fanta_live_mcp` (new crate in fanta-edit)

- **Transport**: port of the old hand-rolled localhost server (zero heavy
  deps): TCP 127.0.0.1:3846, JSON-lines + Streamable HTTP `POST /mcp`,
  localhost Origin check. Started from `fig_viewer::init` behind a setting
  (`fanta.live_mcp.enabled`, default on in dev builds).
- **Dispatch**: the GPUI twin of the old chokepoint — the listener thread
  parses JSON-RPC, then `AsyncApp::update` onto the main thread to a
  `LiveMcp` global holding `WeakEntity<Workspace>`. Tool handlers resolve the
  active (or addressed) `FigView`/`FigItem` and mutate through fig_viewer's
  existing operation seam (undo/redo preserved for free).
- **Tool surface (lean core, not 207)**:
  - Read: `get_editor_state`, `get_document`, `get_node`, `batch_get`,
    `snapshot_layout`, `get_screenshot` (export.rs render), `get_guidelines`.
  - Write: `batch_design` — a JSON op list (create_node, set_props, move,
    reparent, delete, group, set_fill/stroke/text/…) executed as ONE
    transaction: validate on clone → apply → solve layout → single undo stop.
    Individual high-frequency conveniences (`create_frame`, `set_property`,
    `place_image`) delegate to it.
  - FNX: `read_fnx_source`, `edit_fnx_source` (string-replace w/ validation
    via fanta_fnx before write), `list_project_files` — the disk lane the
    reload debounce was built for.
  - Media: `place_generation` — takes a fanta-backend generation_id/asset
    URL, downloads, inserts as Image node at a rect. (Generation itself stays
    on the backend MCP — the editor only places results.)
  - Journal: every write logged (port journal.rs) — F1/F5 discipline.
- **tools.json compat**: `dump_tool_specs` equivalent kept so external
  harnesses can diff the surface.

### 2. Native agent tools (agent panel)

Register the same core as built-in agent tools (design_read, design_batch,
design_screenshot, fnx_edit) via the agent crate's tool registry so the
built-in agent works with zero MCP config. Thread rendering: design_batch
renders a card with the post-edit screenshot; generation tools render the
image/video inline with a "Place on canvas" action — media lands in the
thread first, then onto the canvas (the innovative loop: prompt → thread
preview → place → refine by talking).

### 3. Media skills (agent_skills)

A `fanta-design` skill (port of the old shared SKILL.md, updated for v2
verbs) + `fanta-media` skill teaching generate→poll→place via the backend
MCP (context_servers entry `fanta` at https://api.fantaisa.net/mcp, staged
on the integration branch). Video: `animate_image` → wan-2.2-i2v — requires
the `videogen` Modal family deployed (imagegen is live; videogen is next in
the runbook order).

### 4. Collaboration (enterprise flagship)

Pending the collab research report: the in-tree collab server deployable +
control-plane token mint (Wave 8 docs), plus fig_viewer comments as the
first co-presence surface. Tracked separately.
